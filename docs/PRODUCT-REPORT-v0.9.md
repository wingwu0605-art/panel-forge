## 三、分镜类软件功能对照（竞品视角）

| 产品 | 定位 | 强项 | 我们相对位置 |
| --- | --- | --- | --- |
| **Boords** | 在线分镜协作 | 分镜卡、版本对比、团队评论、AI 生图 | 我们**强在格子几何与印刷版式**，弱在协作与版本对比 |
| **Storyboarder**（Wonder Unit） | 开源桌面 | 极速草图、3D 预览、镜头时长 | 我们强在漫画版式与导出，弱在手绘速度 |
| **Toon Boom Storyboard Pro** | 工业级 | 时间轴、镜头、动画分镜、多轨音 | 我们不做动画时间轴（也不需要） |
| **CSP 分镜/コマ割り** | 绘画软件内置 | 格子框工具、网点、文字 | 我们**模板化更快**，但绘画深度远不如 |
| **Canva / Storyboard That** | 轻量 | 拖拽、模板多、零门槛 | 我们的模板更"像漫画"，但无素材库 |
| **Midjourney/即梦类** | 出图 | 出图质量 | 我们不做模型，做**前置结构**（版式+提示词） |

### 可借鉴并值得加的（来自上述产品）

1. **镜头时长/页节奏**（Storyboard Pro）：给每页标"预计阅读秒数"，辅助排版节奏（我们已有节拍数据，加一行即可）。
2. **版本对比**（Boords）：同一格保存多张"候选"，左右对照选一张 —— 我们已有候选图机制，缺对照 UI。
3. **分镜卡导出为图片集**（Boords）：把分镜表导成"卡片 PNG"，方便发给甲方过稿。
4. **模板混合**（CSP 格子框）：允许在一页里手动切一格出来（裂格/合格），比换模板灵活。
5. **素材库**（Canva）：网点/集中线/道具等可拖入的素材（我们已有气泡库这一套，可扩成通用素材库）。

## 四、版本迭代约定（不再重复创建"第一版"）

从本次起采用语义化版本 + 变更日志 + 标签，**所有改动都进同一条主线**。

| 文件 | 作用 |
| --- | --- |
| `VERSION` | 唯一版本源（`0.9.0`） |
| `CHANGELOG.md` | 按 Keep a Changelog 记录每轮改动（含历史压缩版） |
| `package.json` → `version` | 由 `scripts/set-version.mjs` 同步 |
| `native/android/app/build.gradle` | `versionName` / `versionCode` 由构建脚本从 `VERSION` 读取 |
| git tag | 每次发版打 `vX.Y.Z` |

**版本号规则**

- `0.x` = 还在补齐画师核心能力（现在）
- `1.0` = 到达"能独立完成一话漫画"的门槛（PSD、图层、字体排版、PSD 旁挂）
- 之后：`1.y` 加功能、`1.y.z` 修 bug

## 五、架构与质量约定

**架构原则（本项目实际执行的）**

1. **零框架、零构建**（网页）：原生 ES Module + `server.mjs`/静态构建。好处是十年后还能打开；坏处是没有类型系统 —— 用"单测 + 目视回归"补。
2. **数据自己拥有**：模板几何、提示词、气泡、绘制成图全是纯数据（JSON + PNG），引擎只是渲染器。所以换 Klecks 不伤数据。
3. **一条渲染真相**：SVG 由 `lib/svg.mjs` 单一实现，网页与导出共用，杜绝"所见非所得"。
4. **分层**：`lib/`（纯函数，Node/浏览器共用）→ `web/`（界面）→ `server.mjs`（HTTP）→ `native/`（壳）。纯函数层有单测覆盖。
5. **平台能力升级（"最新应用架构"的具体落点）**：`:has()`、容器查询、`color-mix()`/`oklch()`、View Transitions、`popover`/`dialog`、CSS 嵌套。本轮已用 `oklch` 重写主题色板、用 `color-mix` 生成状态色。
6. **性能分档**：浏览器 / 壳（WebView）两套预算，靠 `body[data-shell]` 切换（关模糊、压动画、热区提层）。

**质量门槛（每次提交必须满足）**

```
node scripts/validate.mjs        # 138 套模板版面体检
node scripts/test-units.mjs      # 纯函数 49 项
node scripts/test-llm-mock.mjs   # AI 链路 31 项（本地假模型）
node scripts/visual-check.mjs    # 真浏览器 160 项
node scripts/check-contrast.mjs  # 配色 60 对（6 套色板 × 10 组，WCAG 2.2 AA）
```

五套全绿才允许提交；任何一项挂了先修再提。这条规则从 v0.9.0 起写死在本报告里。

## 六、两套配色（本次交付）

两套都是**多色系、高级感**，不是单色偏冷，用 `oklch` 定义保证感知均匀（同明度下色彩强度一致）。

### 6.1 灵动可爱（Cute）

关键词：**暖、圆、弹、糖果色**。适合爱好者、条漫、轻喜剧。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `oklch(0.977 0.014 330)` | 底色偏奶粉 |
| `--bg-elev` | `oklch(0.995 0.006 330)` | 卡片 |
| `--tint` | `oklch(0.66 0.20 350)` | 主色：莓红 |
| `--accent-2` | `oklch(0.74 0.16 55)` | 次色：蜜橙 |
| `--ok` | `oklch(0.72 0.16 155)` | 成功：薄荷 |
| `--warn` | `oklch(0.80 0.16 90)` | 提醒：奶黄 |
| `--r-xl/lg/md` | `26 / 20 / 14px` | 圆角更胖 |
| 动效 | `--spring: cubic-bezier(.34,1.56,.64,1)` | 带回弹 |

### 6.2 高级简约（Minimal）

关键词：**冷灰、留白、细线、单一强调**。适合职业画师、出版过稿。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `oklch(0.972 0.002 265)` | 近中性底 |
| `--bg-elev` | `oklch(1 0 0)` | 纯白卡片 |
| `--tint` | `oklch(0.55 0.13 258)` | 主色：靛蓝（低饱和） |
| `--accent-2` | `oklch(0.62 0.06 265)` | 次级灰蓝 |
| `--sep` / `--card-border` | `oklch(0.90 0.004 265)` | 发丝线 |
| `--r-xl/lg/md` | `16 / 12 / 9px` | 圆角收敛 |
| 阴影 | 单层极浅 `0 1px 2px oklch(0 0 0 / .05)` | 不抢内容 |
| 动效 | `--spring: cubic-bezier(.2,.8,.2,1)` | 干脆无回弹 |

两套都通过 `html[data-skin]` 切换，**只作用于令牌**，组件代码零改动；
与「液态玻璃」可叠加（玻璃管材质，皮肤管色板与圆角）。

## 七、下一步（按建议顺序）

1. **真机回归**（半天）：APK 装到手机，验四条（导出→相册、分享选择器里有没有绘世界、分享回来填格、帧率）
